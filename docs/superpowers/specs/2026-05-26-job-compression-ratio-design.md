# Job Compression Ratio — Design

**Date:** 2026-05-26
**Status:** Approved (pending user review of this spec)
**Scope:** Replace the misleading single "Compression Ratio" field in the job detail sheet with two accurate values — Dedup Ratio and Compression Ratio — sourced from new `AvgDedupRatio` / `AvgCompressRatio` columns in the `jobSessionSummaryByJob` section. Gracefully degrade when the source JSON predates these fields.

## Background

`src/components/dashboard/job-detail-sheet.tsx` renders a "Compression Ratio" property row in the Storage & Sizing section, computed via `formatCompressionRatio(SourceSizeGB, OnDiskGB)` in `src/lib/format-utils.ts`. The formula is `Source / Disk`.

That value is **not** a compression ratio. It is the **total data reduction** ratio — the combined effect of deduplication _and_ compression. Veeam reports these as two separate numbers, and the current label conflates them.

Newer healthcheck reports (confirmed against `Veeam Health Check Report_VBR_localhost_2026.05.26.123917.json`, generated by VBR 13.0.1.2067) emit the two component ratios directly in the `jobSessionSummaryByJob` section as `AvgDedupRatio` and `AvgCompressRatio`. Older healthchecks (e.g. the project's existing `veeam-healthcheck.example.json` from VBR 13.0.1.1071) omit both columns entirely.

This change uses the new fields as the authoritative source and removes the legacy `Source / Disk` calculation so the inaccuracy cannot creep back in.

## Data Model

### `SafeJobSession` additions

```ts
export interface SafeJobSession {
  JobName: string;
  MaxDataSize: number | null;
  AvgChangeRate: number | null;
  SuccessRate: number | null;
  SessionCount: number | null;
  Fails: number | null;
  AvgJobTime: string | null;
  MaxJobTime: string | null;
  AvgDedupRatio: number | null; // NEW
  AvgCompressRatio: number | null; // NEW
}
```

`EnrichedJob` is `SafeJob & { sessionData: SafeJobSession | null }` and picks up the new fields automatically — no code change there.

### Normalization rules

| Source value           | Stored value | DataError? |
| ---------------------- | ------------ | ---------- |
| `"3.03x"`              | `3.03`       | No         |
| `"3.03"` (no suffix)   | `3.03`       | No         |
| `""` (empty string)    | `null`       | No         |
| Field omitted entirely | `null`       | No         |
| `"abc"` (garbage)      | `null`       | **Yes**    |

The empty-string case is expected — Veeam emits `""` for jobs with no successful sessions, and old healthchecks omit the column entirely. Both are non-error states. Only true junk values get a `DataError` (consistent with `parseNumeric`'s behavior on bad numerics today).

### `parseRatio()` helper

Lives in `src/lib/normalizer.ts` alongside `parseNumeric`. Private; not exported.

```ts
function parseRatio(
  value: string | null | undefined,
  section: DataError["section"],
  rowIndex: number,
  field: string,
  dataErrors: DataError[],
): number | null {
  if (typeof value !== "string") return null;
  const trimmed = value.trim();
  if (trimmed.length === 0) return null;
  // Strip trailing 'x' / 'X' if present
  const stripped = trimmed.replace(/[xX]$/, "");
  return parseNumeric(stripped, section, rowIndex, field, dataErrors);
}
```

Reusing `parseNumeric` keeps the DataError-on-garbage behavior consistent with the rest of the normalizer.

## Format Helper

`formatRatio` replaces `formatCompressionRatio`:

```ts
export function formatRatio(value: number | null): string {
  if (value === null) return "—";
  return `${value.toFixed(2)}x`;
}
```

**Precision change:** `toFixed(2)` rather than the old helper's `toFixed(1)`. Veeam reports two-decimal precision in the source (`"3.03x"`, `"1.56x"`); rounding to one decimal loses information without any compensating benefit.

**Em-dash for `null`:** the format helper returns `"—"`. The detail-sheet wrapper (`RatioValue`, below) is what attaches the tooltip — the helper stays pure and tooltip-free so other future consumers can reuse it.

The legacy `formatCompressionRatio(sourceGB, diskGB)` is **deleted**, not deprecated. No other production code imports it (verified via grep across `src/`).

After:

The unused `formatCompressionRatio` import is removed.

### `RatioValue` (file-local component)

Sits in `job-detail-sheet.tsx` next to `BooleanValue`, `NullableValue` etc. — same pattern, not exported.

```tsx
function RatioValue({ value }: { value: number | null }) {
  if (value === null) {
    return (
      <Tooltip>
        <TooltipTrigger asChild>
          <span className="text-muted-foreground inline-flex cursor-help items-center gap-1">
            —
            <Info aria-hidden="true" className="size-3" />
            <span className="sr-only">
              Not reported by this healthcheck version
            </span>
          </span>
        </TooltipTrigger>
        <TooltipContent>
          Not reported by this healthcheck version
        </TooltipContent>
      </Tooltip>
    );
  }
  return <span>{formatRatio(value)}</span>;
}
```

- **Em-dash + ⓘ icon** together: em-dash alone reads as "no data"; the icon signals "there's a reason — hover."
- **`cursor-help`** reinforces hover-ability.
- **Icon:** `Info` from lucide-react at `size-3`.
- **Accessibility:** `aria-hidden` on the icon paired with `sr-only` text, matching the project's icon-with-text convention. Tooltip content is announced via the shadcn tooltip primitive's built-in semantics.

### Tooltip primitive

Project uses shadcn 3.8 (`components.json` style `new-york`). If `src/components/ui/tooltip.tsx` is missing, add it via:

```
npx shadcn@latest add tooltip
```

This is the standard project pattern for new shadcn primitives. Verify before assuming — the file may already be present.

## Testing Strategy

### `src/__tests__/normalizer.test.ts`

Add cases inside the existing `jobSessionSummary` describe block:

- `"3.03x"` → `3.03`
- `"3.03"` → `3.03`
- `""` → `null`, no DataError pushed
- field key absent from record → `null`, no DataError
- `"abc"` → `null` **and** a DataError emitted with `field: "AvgDedupRatio"` (or `AvgCompressRatio`)

### `src/__tests__/format-utils.test.ts`

- Delete `describe("formatCompressionRatio")` (8 `it()` cases).
- Add `describe("formatRatio")`:
  - `formatRatio(null)` → `"—"`
  - `formatRatio(3.03)` → `"3.03x"`
  - `formatRatio(1)` → `"1.00x"`
  - `formatRatio(0)` → `"0.00x"`

### `src/__tests__/job-detail-sheet.test.tsx`

Delete the two existing compression-ratio tests (lines 97-119 today).

Add:

1. Renders `Dedup Ratio` row with `"3.03x"` when `sessionData.AvgDedupRatio = 3.03`.
2. Renders `Compression Ratio` row with `"1.56x"` when `sessionData.AvgCompressRatio = 1.56`.
3. Renders muted `"—"` with tooltip trigger when `AvgDedupRatio` is `null` — assert the `sr-only` text `"Not reported by this healthcheck version"` is present.

Tests use `userEvent.hover` only if directly asserting tooltip visibility; otherwise the `sr-only` text assertion is sufficient and tooltip-library-agnostic.

### `src/__tests__/domain-types.test.ts`

## Out of Scope

- **Jobs table column** for either ratio. The table doesn't show this today; adding a column is a separate UX decision (sortability, density, mobile layout).
- **Charts or aggregations** based on the new ratios.
- **Validation rules** using ratios (e.g. "warn if dedup is unusually low"). No product requirement exists.
- **`AvgBackupSize` / `MaxBackupSize` / `AvgDataSize` / `Retries` / `WaitCount` / `AvgWait` / `JobTypes`** — other new session-summary columns visible in the newer healthcheck but not requested in this fix.

## Open Risks

- **Shadcn tooltip may need to be added.** Low risk — adding a shadcn primitive is a single command and the project already follows that pattern.
- **`AvgChangeRate` precision precedent.** The project rounds change rate to `formatPercent(rate, decimals=1)`. We're choosing two decimals for ratios because Veeam's source data is two decimals. If consistency with other percentages matters more than fidelity, this is reviewable in the PR.
- **Tooltip in tests.** Some tooltip libraries don't render `TooltipContent` until hover. The test strategy leans on `sr-only` text (always in the DOM) to avoid a dependency on hover simulation.
